# Portfolio binding and coverage v1

`neural_foundry.portfolios` exposes opaque native gym-source and portfolio-planning witnesses. Importing it performs no Torch import, dynamic gym discovery, package install or model execution. Explicit `builtin(head)` performs local finite native arithmetic factory/oracle/scorer probes; `user(snapshot, approval)` needs the actual T027 snapshot and T028 approval witnesses. A DTO, manifest hash or claimed validation string cannot construct either witness.

## Exact source composition

The five registered arithmetic sources are hand-constructed public synthetic fixtures. Each is probed on all 289 integer pairs using actual native model forward, independent direct arithmetic truth, and wrong/empty/nonfinite scorer probes. Exported validation bytes bind the descriptor, actual observations and native probe code; their digest is the manifest validation reference. These finite probes do not prove general scorer correctness, adversarial robustness or real-model quality.

A custom source retains its exact snapshot, code/data/dependency/image identities, interface/scorer/oracle bindings, license/confidentiality and limits. It uses the original verified validation plan from CAS, not caller-proposed metric names/ranges. Its raw metric is named `score`, with the original validated bounds; arbitrary reward is never relabeled accuracy. Approval is exact-version and historical-runtime-specific: execution still requires the separate qualified sandbox/environment recheck. Binding a source never imports its Python into the controller.

`compose(portfolio, coverage, sources)` validates the existing strict native `GymPortfolio` contract and requires one live exact source per manifest. It preserves per-gym objective IDs, roles, metric directions/units/statistics/weights, hard thresholds, exact split declarations and schedules without flattening identities. Altered or missing manifests, validation references, duplicate gyms, negative/nonfinite weights, illegal split-role overlaps, incomplete required roles/gates and mismatched objectives fail. Coverage and curriculum hashes must bind the actual typed coverage plan and ordered binding/schedule pairs. Round-trip records retain identical identities. Changing schedules, constraints, sources or coverage creates a new planning identity, not an in-place mutation.

The planning witness `portfolio_id` hashes the complete portfolio/coverage/report bundle. `contract_portfolio_digest` is separately the canonical core `GymPortfolio` digest used by study contracts. A five-gym declaration requires five distinct named required gyms and retention plus target/independent-final roles; an exploratory profile can use fewer. Neither is an assurance *pass*: the report explicitly keeps `standard_five_gym_passed=false`.

## Coverage and intervention gaps

Coverage links resolve exact binding IDs and bound metrics. Dimensions include target tasks, protected behaviors, mechanism, context boundaries, cache correctness, tools, latency, memory and safety. Target and protected coverage are mandatory. Only finite fixture-observed target/retention capabilities are supplied by the initial source registry. Labeling arithmetic accuracy as latency, cache correctness, causal mechanism or safety cannot upgrade that evidence. Missing and weak/unsupported dimensions remain visible with a recommendation for an independently validated gym/protocol.

An architecture-surgery plan forces context-boundary, cache-correctness and runtime-latency coverage to be mandatory even when the submitted JSON says optional or omits them. Current arithmetic/custom finite probes do not supply those protocols, so these gaps block that plan. No agent acknowledgement or weight can waive mandatory gaps. The later workflow/intervention resolver must bind its actual intervention to this frozen coverage policy; this planning API alone authorizes no surgery.

Reports show duplicate data-source counts rather than assuming independent evidence from different gym names. The deterministic schedule retains every constituent binding and its weights, returns due/deferred-required status for a candidate ordinal, and always schedules final-required checks at final verification. Unique task/group counts deduplicate shared identities across suites. A deferred required measurement still cannot pass hard-gate assessment by being omitted.

The cost envelope is a checked conservative sum of scheduled episode wall/output limits. CPU, memory peaks and setup/runtime overhead remain unknown, not zero. This is not study budget admission, a reservation or a dispatch grant.

## Hard gates without weighted compensation

`assess_bytes` accepts a bounded, strict record of supplied observations keyed by planning identity, binding, metric and original/no-op/best-known comparator. Units/statistics must match the frozen schema; duplicate or unknown keys and out-of-range/nonfinite values fail. Each row retains raw value, baseline, direction-aware gain, status, threshold, weight and gate result. Missing/timed-out/failed data or a missing required baseline fails its hard gate. A required failure cannot be hidden by high weights or successes elsewhere. No aggregate weighted acceptance score is emitted.

Supplied observations are **unverified measurements**, not execution/evidence receipts. `constraints_satisfied` is only a deterministic constraint assessment. `scientific_acceptance=false`, `outputs_eligible=false` and dispatch denial stay explicit. Paired execution controls, calibrated uncertainty, interference and scientific acceptance are later tasks.

## Split custody and execution boundary

Composition checks and freezes split *declarations* using the core schema. It does not assert that declaration-only exposure history is actual custody, mint split tokens, expose labels, or override T029/T030 broker/history checks. Records set `split_custody_verified=false` and `dispatch_allowed=false`; schedules are metadata, not read authority. Current source evidence is finite fixture-only, and broader generalization claim scopes are rejected. The later study/workflow resolver must reconcile actual registered split catalogs, exposure history, live approvals/environment, budget/lease and finalized panel before execution. Public synthetic fixtures and a development-only user package do not become independent held-out evidence by composition.
