# Trusted Torch edit backend v1

`nf.trusted_torch_cpu` version `1` is an explicit frozen compiler policy, not an arbitrary Python operation registry. `models.edit(runtime, plan, smoke_suite)` accepts opaque live qualified runtime and compiled-plan witnesses. A native-only plan cannot authorize Torch dispatch. The T032 trusted host runtime remains distinct from the T026 hostile-gym OCI sandbox. No model downloads, GPU qualification, remote code, optimizer, backward pass, training, or Python editor callbacks are implemented.

## Paired execution and admission

Rust revalidates the source, native execution/smoke binding, lineage/method history, effective alias masks, numerical constraints and operands. Native reference execution makes an isolated candidate but does not publish a Torch witness. The fixed, hash-bound child restores the actual registered factory and source tensors, then receives only typed compiled instructions, native-verified operand bytes and the explicit numerical policy. Unknown operations/modes fail. Every operation executes under `torch.inference_mode()` with gradients disabled and no optimizer API.

Replace, delta, scale, mask, axis permutation, left/right linear map, left/right projection and low-rank updates preserve shapes. Float32/float64 target and accumulation precisions are explicit. Matrix products use separate multiply/add accumulation in the declared order rather than assuming a BLAS/FMA tolerance. Intermediate and output casts are explicit and policy-bound; there is no dtype inference/fallback. Recipes, graph/config/tokenizer changes, buffers and packing changes are not supported.

The child returns actual full bytes and actual parameter/buffer/alias observations after EVERY instruction. Rust checks shape/dtype/device/stride/gradient state and storage-equality membership, hashes actual bytes itself, and checks every changed cell against that instruction's alias-expanded target region. An outside-scope mutation is rejected even if a later operation restores final bytes. Buffer and source state are immutable. Every final byte must equal the independent native candidate, including signed zeros and untouched state. A nonzero declared backend tolerance does not loosen this initial profile: differences reject, never silently substitute native results.

The actual edited Torch model runs the frozen smoke inputs; Rust compares its outputs against the native materialized candidate, using the T032 finite CPU forward tolerances (1e-5 f32, 1e-10 f64). The final state is re-observed after forward. The native candidate is returned only after Torch byte equality, scope and smoke checks prove it is exactly the same state. Its core manifest, transaction/effects/method/ancestry identities remain intact; a separate non-deserializable edit witness binds actual Torch execution, runtime, compiled plan and core candidate. A native reference candidate by itself is not a Torch execution witness.

## Bounds and measurements

This initial CPU profile supports at most 16 instructions, at most 64 KiB of verified operand transfer, and a conservative full-state trace budget of 64 KiB of raw logical bytes (aliases included). These are explicit limitations, not large-model claims. Typed output remains bounded by the T032 process-output and canonical-parser limits. Source preflight, exact inventory, numerical bounds, cancellation, pidfd cleanup and runtime/source digest fences are unchanged.

Copy receipts distinguish native source transfer, owned bytearray staging, Torch clone, factory storage, operands, inputs and per-step trace serialization. An explicit cumulative allocation counter covers tensor results/casts and cloned operands; source copy/staging and operand staging are conservatively charged in addition. This tracked data allocation must fit the frozen program temporary-byte limit and the 64 MiB adapter ceiling. It is conservative cumulative allocation, not an allocator-derived live high-water mark. Tensor headers, interpreter/observer/library allocations are not claimed to be fully measured by that counter. Actual kernel `wait4` CPU and peak RSS cover the complete fixed child process/all its threads; RLIMIT_AS is the hard virtual-address bound, not a hard RSS bound. No zero-copy claim is made.

Runtime setup and the additional parent/native-reference/materialization work are outside that child CPU measurement and remain additional unknown costs; this standalone API does not grant study-budget/lease authority. Incomplete/failed/cancelled or unverifiable runs admit no edit candidate. Intent/execution/completion records remain private. Cleanup precedes successful admission. `outputs_eligible=false` and `promotion_status=not_evaluated` remain explicit: verified mechanics and synthetic arithmetic parity do not establish scientific acceptance or real-model research success.
