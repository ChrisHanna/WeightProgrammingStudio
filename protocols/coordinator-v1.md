# Durable contracts and coordinator leases v1

`nf_experiments::coordinator::Ledger` stores real SQLite transactions on qualified Linux storage. `freeze`, `contract`, `state`, `events`, `acquire`, `renew`, `release` and `advance` are Rust APIs; no Python coordinator state substitutes for them. The ledger records workflow state, not scientific acceptance, artifact validation, supervision cleanup, spend reconciliation or deployment.

## Immutable freeze and revisions

Freeze validates the typed StudyContract and atomically stores complete canonical bytes, their content digest, exact family/revision/parent, initial state and a freeze event. Repeating identical input returns the same ID with no duplicate event. Edited drafts cannot reuse a revision. The initial family starts at revision one; subsequent revisions extend exactly the current head and require a distinct approval receipt reference. The reference itself is not proof of human consent: authoritative receipt/artifact/policy resolution remains preflight.

A live coordinator must release before a new revision can freeze. Once the family head changes, old revisions cannot acquire or commit worker state, even with an otherwise unexpired old token. Source records, stages and events remain readable. Contract/event/family-budget/final-reservation tables have update/delete-denial triggers. Reads independently verify canonical identity, so a body changed after bypassing a trigger is rejected rather than trusted.

The immutable family-budget origin is retained separately from revisions; this task records no fabricated zero spend. Revisions may preserve or reduce limits, never reset/increase them behind a new revision ID. An increased-budget approval capability is not implemented here. Actual cumulative reservations/cost reconciliation belong to T023 and later events. A separate family identity is not a license to bypass approval/lineage or exposure checks.

## Fencing, expiry and journals

Only an opaque non-deserializable Lease returned by `acquire` can renew/release/advance. It binds store nonce, exact contract, owner, monotonically increasing family fencing token, kernel boot ID and expiry. All competitors are denied while any lease is live, including a caller guessing the same owner name. Restarting a process does not reset kernel BOOTTIME. A reboot invalidates old boot-bound capabilities; expiry never revives a stale owner. Lease TTL is finite (up to five minutes), read from the actual monotonic kernel clock, not a caller-supplied timestamp.

Each transition is an immediate SQLite transaction that checks the latest revision and exact lease fields, expected stage, legal edge, operation ID and finite event bounds before appending an immutable canonical event and updating its state head together. The event carries previous hash, sequence, coordinator fence/owner, boot/monotonic/wall-clock observations, protocol/evidence references and reason. Identical operation retries return the original event, while changed input under an existing operation ID is an idempotency conflict. Stale leases cannot use retry handling to bypass authority.

Read-state snapshots verify the complete bounded journal chain and head, including older events, identity/order/operation/stage edges and nondecreasing fencing tokens. Readers use a stable SQLite transaction so a concurrent append cannot appear as a corrupt extra tail. Event pages are bounded and verify the journal before returning records. These hashes detect corruption; a private local database is not a signature against a malicious filesystem owner who rewrites all metadata coherently.

Allowed stages start Frozen -> Preflight -> Profile -> Baseline and follow the declared diagnose/design/execute/evaluate/search/verify/learn procedure. Manual design may follow baselines directly. Selection loops are explicit; Verify cannot return to search/design. Completed means the procedure ended, not that weights improved or were accepted. Failed/unsupported/incomplete/cancelled are terminal here. Supervised recovery/resume/cleanup and budget-authoritative dispatch are separate later APIs, not implicit transitions added by a worker.

Entering Verify conservatively reserves the exact final item/group panel in the family ledger. New informed revisions need disjoint new holdout items/groups. This reservation is not a claim that every final task was actually read or evaluated; the full task exposure ledger still records actual access and unknown/crashed work later. No reservation/history deletion API exists.

## Storage and trust boundary

Paths must be explicit absolute non-root directories. Components are walked using no-follow directory FDs; final database type, single-link identity, permission and size are checked, and SQLite uses OPEN_NOFOLLOW. Group/world-writable ledger roots or databases are rejected. Directory/database identity fences and side-file type/link checks run around API work. SQLite transactions use FULL synchronization, foreign keys, trusted_schema off, DELETE journaling, finite busy waits/cache/page/SQL/value bounds and no attached databases. Defaults bound the main DB to 64 MiB, contracts to 1024, events to 100000; read pages contain at most 1000 events. The rollback journal can require additional space up to the database bound and must be included in preflight storage reservation.

SQLite's NOFOLLOW rejects `/proc/self/fd/N/...` because that path includes a kernel symlink. The implementation therefore resolves the already verified directory FD to its physical path, retains its FD/file identity anchors, re-walks/checks that physical directory and uses SQLite's own no-symlink open. It fails on root replacement/renaming rather than treating a new path as the same store. This is not a custom fd-only SQLite VFS or adversarial same-UID filesystem sandbox. The ledger directory must remain controller-owned and inaccessible to untrusted workers; a qualifying separate account/sandbox must enforce that boundary. In-memory filtering is not isolation.

New/foreign schema versions are refused, not silently reinterpreted. Explicit versioned migrations now extend the unchanged schema1 through budgets/schema2, supervision/schema3, split catalogs/final panels/schema4, and exact exposure/legacy intake/schema5, with exact prior hashes and retained records. See the budgets, supervision, split-access and exposure protocols and actual migration tests; old journal formats are not silently rewritten. File/row/page/event limits fail with explicit errors; partial transactions leave no new state/event pair. Missing storage or unavailable kernel boot/clock evidence fails closed.

Tests use real disk SQLite, reopen after close, attempt immutable SQL updates, run competing connections, expire/renew/release real leases, reject stale/foreign/revision tokens, exercise exact/conflicting retries and illegal edges, enforce quotas without partial records, preserve family budgets/final panels, detect old-event corruption, and reject unsafe filesystem aliases/private-root violations/foreign database rewrites. No model or gym executes in these tests.
