# Exact local exposure and legacy intake v1 (coordinator schema5)

## Authority and identity

The Rust coordinator owns an immutable, hash-chained study-family journal. It records exact task/group/task-family identity, package and dataset versions, canonical payload and conservative alias identities, contract/revision, recipient/role, protocol, model/programmer/teacher/candidate references, seed, attempt/retry link, intended/shown fields, lifecycle/outcome, native time/fence and measured/unknown costs. Optional identities and measurements stay null when unobserved, not invented or zeroed. Controller-supplied context is a reference/assertion, not a verified model execution witness or proof a teacher call occurred.

Identity v1 canonicalizes bounded JSON and recursively omits reserved transport keys (`task`, `task_id`, `item`, `item_id`, `group`, `group_id`, `split`, `role`, `name`, `version`, `nonce`). It retains seed and actual task content. The fixed policy identity is recorded. Exact input hashes are retained too. An alias graph joins same item, group or conservative input identity across source versions and revisions; names, paths, role labels, nonce/version changes or reformatting cannot turn known data into unseen data.

This is deliberately conservative, not a general semantic-equivalence algorithm. Legitimate inputs using those reserved keys semantically may collide and be refused as independent; collisions never establish freshness. Near duplicates, rewritten tasks or unknown external contamination require explicit provenance/custody review. The local ledger does not prove what an external model, teacher or human saw. A clean HeldOutGeneralization claim with unresolved external unexposed custody is typed unsupported, not certified from hashes/declarations. Limited local software fixtures remain explicitly limited.

## Events and availability

Every admitted disclosure has separate Requested and Started records before release. Completed records mean bytes were made available to the authorized recipient route, not proof a person read every field or a Python function body executed. Failed, partial, Incomplete and imported unknown histories remain retained. Started records left by crashes are conservative possible availability, never a fresh-data reset.

Fields distinguish identity metadata, inputs, labels, outputs, feedback and summary scores. Direct input/label scope does not imply label access from a summary, but summary/feedback is still exposure and can invalidate clean final evidence. Worker scope welcomes log their exact task-identity disclosures. Native split reads record fields and source versions before CAS I/O, then completed availability or failed/unknown outcome. Actual qualified OCI calculations log the source code identity, availability and measured guest CPU outcome without pretending unmeasured startup costs are zero.

The native fixture inference broker logs verified target-model references and actual model-call counts separately from the recipient's output. Cached replies create new disclosure/retry records with links to prior completed availability, but do not execute or bill another forward. Field-based artifact access accounts for labels/metadata for all associated scoped tasks; generic unassociated tools/staged proposals retain their existing private request/outcome records rather than inventing task associations. Unknown seed/candidate/teacher references remain unknown.

`read_split_traced` accepts explicit controller context where known; the old data-only endpoint retains an unassociated context. `disclose_score` supports actual registered task/version references and bounded finite scalar artifacts for Output/Feedback/Summary only. It cannot deliver input/label payloads disguised as score artifacts, and cannot deliver holdout or post-final feedback into proposer search. The scalar artifact identity is retained. It is not public-export approval or model/scientific acceptance.

## Retained contamination and recovery

Split binding and every disclosure recheck applicable local identity/group history. Cross-role aliases, legacy unknown histories and known/partial/summary exposure cannot be relabeled as fresh selection/holdout. Existing final evaluation may repeat its frozen same-contract final domain/model inputs; new revisions cannot reuse consumed tests. Already authorized development data cannot be erased from memory, but it does not become fresh independent evidence later.

Events contain global family sequence/previous-hash links and operation lifecycle parent links. A repeated identical operation is idempotent; changed evidence under its ID fails. Genuine retry occurrences have distinct operations/context, preserving failed and repeated costs. Native non-deserializable disclosure tickets cannot be used with another store/contract/epoch or reconstructed from JSON to claim success. A fresh fenced coordinator can reconcile expired/dead-boot/old-epoch pending attempts only as Incomplete with unknown costs/no invented shown fields. It cannot change them to successful access or remove them.

Exposure/query APIs and hashes are private controller data. No worker gets the Ledger, coordinator Lease, SQLite credential or entire corpus. Public output policy must omit sensitive payloads, local paths and guessable private hashes. Stronger at-rest encryption/key-custody requirements remain unsupported until actually qualified; this journal is not an encryption or privacy-compliance claim.

## Two-way legacy records

`import_legacy_split` requires actual immutable bounded source bytes and resolves every input/label reference. The strict v1 source contains explicit edit/sealed item/group/family identities and optional per-item historical recipient/fields/seed/attempt/outcome records. A declared retry may point only to an earlier same-task source event. Each historical observation is retained separately, including failed/partial records; declared history is not relabeled as authenticated native observation.

Edit rows are conservatively known exposed. Sealed rows with history are exposed; absent/empty history is unknown, never verified unseen. A sealed filename or user assertion cannot establish secrecy. Imports are immutable/idempotent across resume/revision, retain source identity and all histories, and always return `independent_three_way=false`, `allowed_destination=development_only`. `admit_legacy_role` is a classification check, not a data/dispatch grant; it refuses selection/holdout destinations. A valid new experiment needs separate qualified group-disjoint selection and unexposed holdout evidence, not a two-way DTO renamed to three roles. Legacy input files are never imported or executed as Python.

## Schema and real verification

Schema4→5 appends exposure subject aliases, lifecycle/hash-chain events, retained unknown-history markers and legacy assessments, with immutable update/delete guards. The exact unchanged schema1 through MIGRATION_V4 hashes, all contracts/events/leases/budgets/stops/workers/catalogs/panels/grants/final reservations are preserved. Pre-schema5 activity lacking exact authenticated exposure history receives an explicit retained gap, not an empty/clean history. Such gaps block new clean selection/holdout admission. Migration fixtures remove only their own empty new tables before exercising older formats.

`cargo test -p nf-experiments exposure` verifies real SQLite lifecycle/shown fields/seed/retry/failure, foreign-ticket denial, immutable rows, transport rehash aliases, unknown legacy exclusion, actual expired-coordinator resume and conservative v4 migration. `python -m pytest -q -k legacy_split_intake` uses actual native controller/SQLite/CAS code: known edits migrate only to development, sealed missing history stays unknown, summary/teacher/partial/retry history persists, renamed/rehashed/group-relabeled data cannot create independent roles, and modern native data/score disclosures retain their exact lifecycle and fields. Prerequisites are not mocked or skipped. These are software fixtures, not a real-model novelty or task-quality claim.
